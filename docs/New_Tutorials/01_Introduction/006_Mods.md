# 模组

模组会将游戏资源从地图文件中分离出来。因此，它们永远不能像地图那样直接在《星际争霸》中启动，只能由编辑器处理。模组最终需要被放入地图文件中才能实际使用。地图对这些模组文件的需求关系，就称为依赖项。这样做的好处很容易理解：将游戏数据与地图地形拆开后，一个模组就可以被多个不同地图重复使用。这意味着一种自定义游戏模式可以移植到许多不同设计的场景中，无论出于美术考虑还是玩法需要。

## 模组类型

模组类型在很大程度上取决于它们应用的位置，主要分为两类。更常见的依赖模组包含触发器、数据以及任何非地形编辑器层面的信息。你可以使用编辑器将这类模组上传到 Battle.net。不过，要组成完整游戏，它们最终仍需要作为依赖项添加到编辑器中的某张活动地图上。这种设计让它们成为一种基础的组织与复用结构，适用于任何需要自定义数据的地图。

扩展模组同样包含各种会改变游戏的资料，也是在编辑器中制作的；但不同的是，它们是在 Battle.net 的 “Custom Games” 界面中，通过先选择基础地图、再选择扩展模组的方式应用。这样就实现了地图设计与模组设计的分离。借助这种机制，模组作者可以在不需要显式协作的前提下，以多种方式利用不同地图。扩展模组还可以依赖依赖模组，因此可以将其视为基础依赖模组的一种应用形态。

Observer Interfaces 是扩展模组的一个特殊子类。这类模组只能修改编辑器中的 UI 部分，在自定义《星际争霸》比赛观战体验时尤其有用。这些界面同样可以在观看录像时启用。

## 模组的用途

模组非常适合用来避免重复劳动。假设你设计了一套自定义战役，要在十张地图中延续特殊规则、角色和玩家选择。如果不使用模组，你就必须在战役的每一关中重复构建这些自定义规则。把游戏元素移入一种数据结构，也就是模组，就可以免去反复重建地图的工作。

当你考虑到自定义战役后续还会继续更新时，模组的重要性就更加明显了。如果没有统一的模组依赖项，每次更新都意味着你需要修改每一张地图。你或许可以在不同地图之间复制粘贴数据，但由于无法有效控制这些版本，灾难性错误的风险会始终存在。模组能够组织这些改动，并将它们传播到所有使用该模组的地图中，大幅节省你的工作量。

除此之外，模组还允许你把大型项目拆分成多个独立模组，把游戏设计中的大块内容分离开来。这使多名开发者可以协作完成同一个项目，各自负责不同部分，例如过场动画、数据或地形。

模组也常被用来打包大量资源，以简化 Battle.net 和 Arcade 中的游玩体验。要记住，《星际争霸》的文件会先存储在 Battle.net 服务器上，然后下载到本地供玩家使用。如果一个项目的模组部分在不同版本之间保持不变，即使其他内容发生了变化，玩家也不需要重新下载这些模组。合理使用这一点，既能简化开发流程，也能让线上分享更高效。作为配套，模组文件最大可达 100 MB，而地图最大仅为 20 MB。这鼓励更聪明地使用数据，并提升地图使用自定义资源的能力。
