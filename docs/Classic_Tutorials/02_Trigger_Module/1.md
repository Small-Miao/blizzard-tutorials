## 简介

触发模块是实现玩法和叙事的地方。你可以在这里制作游戏内过场、在游戏过程中生成单位、创建并跟踪目标，以及完成更多内容。

从最基础的层面看，触发器可以理解为一组指令。只要你希望游戏过程中发生某件事，就可以通过触发器告诉游戏“什么时候发生”以及“具体如何发生”。



1. 触发器由以下几个部分组成：

2. **事件** - 这是触发器执行的原因。如果我们想让英雄死亡时结束游戏，那么这个触发器的事件就是“**当一个单位死亡时**”。
3. **条件** - 条件用于确保触发器只会在某些前提成立时执行。以上面的例子来说，当某个单位死亡并触发了事件后，我们会再加一个条件来确认 **死亡的单位就是英雄**。
4. **动作** - 动作是触发器执行时真正会被执行的指令。在这个例子里，当英雄死亡时执行的动作就是“**玩家 1 游戏结束**”。

## I. 设置视图选项

如果触发模块还没打开，请点击编辑器工具栏上的 Trigger Module 按钮，或者按 [F6]。

![img](007-opentriggermodule-triggermodulebutton.jpg)

在正式开始制作触发器之前，我们先快速看看触发模块窗口的几种显示方式。这里会专门设置两个选项，不过也建议你之后自行看看其他选项并试用一下。

### A. 显示子视图

触发器窗口左侧会列出地图中的所有触发器。默认情况下，地图里已经有一个 近战初始化 触发器。

如果你想修改某个触发器中的事件、条件或动作，通常需要双击对应条目，弹出窗口后才能编辑。

不过，如果启用子视图，那么只要单击某个条目选中它，它的内容就会显示在触发器内容区下方新增出来的区域中。要切换 Use Subviews 选项，请点击窗口顶部工具栏上的 Use Subviews 按钮。

![img](008-viewoptions-subviews.jpg)

### B. 隐藏库

《星际争霸 II》中的所有事件、条件和动作都归类在“触发器库（Trigger Libraries）”中，用户也可以创建自己的触发器库。不过这张地图暂时不需要创建新的库，所以我们会把它们隐藏掉。要切换触发器库的显示状态，请点击工具栏上的 “显示库” 按钮，它就在 “Use Subviews” 按钮旁边。

![img](009-viewoptions-showlibraries.jpg)

### C. 更多选项

窗口顶部的 View 菜单中还能找到更多选项。现在我们先不改它们，不过如果你愿意，之后可以花点时间自己试试。



## II. 我的第一个触发器 - 胜利与失败触发器

现在来做触发器！我们先创建两个简单的触发器：当玩家杀死雷兽和坑道虫时判定胜利；当玩家单位死亡时判定失败。

在此之前，我们先删除 近战初始化 触发器。这个触发器包含的是为《星际争霸 II》标准对战地图准备的动作；而我们的地图是自定义地图，不需要采集矿物、建造建筑之类的内容。你可以选中触发器后按 [Delete] 删除，也可以右键后选择 “Clear”。

### A. 失败触发器

失败触发器应在英雄死亡时执行，并在那一刻让玩家 1 失败。

#### 创建新触发器

1. 在触发器列表中右键，选择 New>New Trigger，或按 [Ctrl+T] 创建一个新触发器。

2. 将这个新触发器命名为 “Defeat”。

3. 选中该触发器以显示其内容。

![img](010-fefeat-newtrigger.jpg)

#### 创建新事件

1. 要为触发器添加事件，右键点击 Events 标签并选择 New>New Event，或者左键点击 Events 标签后按 [Ctrl+E]。

![img](011-defeat-neweventwindow.jpg)

2. 在弹出的窗口中，选择 “Unit Dies” 事件并按 “Ok”。

#### 创建新条件

1. 在触发器内容列表中右键，选择 New>New Condition，或者按 [Ctrl+K]。

2. 弹出的窗口中列出了可选的条件类型。选择 Comparison 条件类型，然后按 “Ok”。之所以选择 Comparison，是因为我们要比较死亡的单位是否就是英雄单位。如果两者相同，那么条件为真，触发器的动作就会执行。

![img](012-defeat-newconditionwindow.jpg)

3. 选中刚创建的条件后，你就能在子视图区域看到它的内容。这里应该包含 “Value 1”、“Operator” 和 “Value 2” 字段。

![img](013-defeat-conditioncontents.jpg)

4. 双击 Value 1 字段，从弹出的条件列表中选择 “Triggering Unit”。Triggering Unit 指的是具体导致该触发器运行的单位。在这里，也就是死亡的那个单位。

![img](014-defeat-conditionvalue1.jpg)

5. Operator 字段用于指定我们希望两个值之间满足什么关系。这里实际上只有两个选项：相等（==）或不相等（!=），因为被比较的两个单位要么是同一个，要么不是，不存在“有点一样”这种情况。这里我们保持 “==”，因为我们希望当死亡的单位是英雄单位时触发器执行。

![img](015-defeat-conditionvalue1selected.jpg)

6. 双击 Value 2，再次打开条件选择窗口。这次我们不从条件列表中选择条件，而是使用列表上方那排单选按钮切换可选值的类型。当前显示的是条件函数列表。选择 “Value” 单选按钮，切换为地图上已存在单位的列表。此前在制作地图地形、为玩家 1 放置单位时，我们放了 2 个陆战队员和 1 个 Jim Raynor (Commando) 单位。找到 Jim Raynor (Commando)，选中后按 Ok。

![img](016-defeat-conditionvalue2.jpg)

#### 创建新动作

1. 在触发器内容列表中右键，选择 New>New Action，或者按 [Ctrl+R]。

2. 在弹出的动作列表中，找到并选择 “End Game For Player”。如果在 “Find” 字段中输入全部或部分目标名称，也能帮助缩小搜索范围。

![img](017-defeat-newactionwindow.jpg)

3. 选中这个动作后，会像先前的条件一样显示其内容。

![img](018a-defeat-subviewhighlighted.jpg)

4. 双击 “Type” 字段，把值从 “Victory” 改为 “Defeat”。

#### 测试一下！

![img](018b-defeat-completedtrigger.jpg)

我们的第一个触发器完成了！现在进入游戏测试一下。

1. 点击编辑器工具栏最右侧的 “Test Document” 按钮，或按 [Ctrl+F9]。

![img](019-testtriggers-testdocumentbutton.jpg)

2. 进入地图后，选中你的单位并命令他们攻击 Jim Raynor。当他死亡时，你应该会看到如下所示的 Game Over 菜单：

![img](020-testtriggers-defeatscreen.jpg)

### B. 胜利触发器

接下来我们要制作一个简单的胜利触发器。当地图上放置的坑道虫与雷兽都死亡时，这个触发器会让玩家 1 获得胜利。

如果你还没有在地图上放置 Nydus Worm 和 Ultralisk (Burrowed) 单位，现在就去放置。关于如何在地图上放置单位，请参见本教程系列第一部分中 [地形模块](../../01_Terrain_Module/3) 的单位章节。我们把这两个单位放在了地图的农田区域：

![img](-003-victorytrigger-placedunits.jpg)

在制作这个触发器之前，我们需要先为任务中要击杀的这两个单位分别创建一个变量。

#### 变量！

《星际争霸 II》编辑器中的变量，工作方式与脚本和编程语言中的变量完全一样。

如果你不熟悉这个概念，可以把变量理解为一个可被赋值的标识符。比如如果 a 是我们的变量，那么我们可以设定 a = 5。此后在公式中使用 a，就等于在使用数字 5，所以 a + 2 = 7。变量的值随时都可以改变。也就是说，在做完 a + 2 这个运算后，我们可以把 a = 5 改成 a = 6，那么下一次在公式里使用 a 时，就会用到数字 6 而不是 5。在《星际争霸 II》编辑器中，我们还可以创建很多不同类型的变量，比如单位、整数和文本。

#### 在触发模块中创建变量

1. 在触发器列表中右键，选择 New>New Variable，或按 [Ctrl+B]。把新变量命名为 NydusWorm。

2. 选中这个变量后，你可以在右侧看到它的内容。每个变量都有一个类型，对应它可以存储的值的种类。变量可以存储整数、实数、文本、单位等等。这里我们把这个变量的类型设为 “Unit”，因为我们希望它保存地图上放置的那个特定坑道虫单位。

![img](021-victory-newvariable.jpg)

3. 双击右侧区域中的 “Initial Value” 字段。

4. 选择 “Value” 单选按钮，然后找到并选中 Nydus Worm (Canal) 单位。

![img](022-victory-selectnyduswormunit.jpg)

5. 按照同样的步骤，再为雷兽创建一个变量。

现在我们就可以开始创建胜利触发器了。继续新建这个触发器。

![img](023-victory-newtrigger.jpg)

#### 事件

上一个触发器使用的是“每当一个单位死亡时”执行的事件。这次我们改用一个叫做 Periodic Event 的事件，让触发器按固定时间间隔重复运行。

1. 在触发器区域中右键，选择 New>New Event，或按 [Ctrl+E]。

2. 然后在弹出的窗口中，从 Function 区域选择 Periodic Event。

3. 将 Duration 的值从 5.0 改为 1.0。

4. 保持 Time Type 为 Game Time。

#### 条件

这个触发器需要两个条件，分别对应我们要检查的两个单位。

1. 在触发器区域中右键，选择 New>New Condition，或者按 [Ctrl+K]。

2. 将条件类型选为 “Comparison”，然后按 Ok。

3. 选中新建的条件，在子视图区域中查看其内容。

4. 将 Value 1 改为 “Unit is Alive”。

5. 将 Unit 的值设为我们刚才创建的 NydusWorm 变量。

6. 双击 Value 2 打开值选择窗口，确认 “True” 复选框未被勾选，然后按 “OK”。因为我们希望在单位“不存活”时触发器运行，所以要把 Value 2 设为 False。

![img](024-victory-truecheckbox.jpg)

7. 对雷兽重复步骤 1 到 6。为了省点时间，你可以复制第一个条件后只改其中的 “Unit” 变量，因为第二个条件除了这个之外都一样。

![img](025-victory-twoconditions.jpg)

当一个触发器中有两个条件时，只有两个条件都为真，触发器动作才会执行。如果你想让触发器在“两个条件任意一个为真”时执行，可以添加一个 “Or” 条件，并把其他条件创建在这个 Or 条件内部。这样只要 Or 条件中的任意一个子条件为真，整个判断就为真，触发器就会运行。

在我们的例子里，必须同时击杀坑道虫和雷兽才能获胜，因此这里不使用 Or 条件。

#### 动作

再创建一个与前面相同的 “End Game For Player” 动作，不过这次请确保它结束游戏的方式是 Victory，而不是 Defeat。

![img](026-victory-completedtrigger.jpg)

### C. 文件夹

保持触发器整洁有序非常重要，所以在进入下一节前，我们先在触发器列表中新建一个文件夹，并把 Victory、Defeat 以及变量都拖进去。

1. 在触发器列表中右键，选择 New>NewFolder，或者先左键点击触发器列表让它获得焦点，再按 [Ctrl+G]。

2. 像在桌面上拖放文件和文件夹一样，把你的触发器和变量拖进这个文件夹。

在接下来的教程中，你会看到我们创建多个文件夹，按用途来分组触发器：胜利与失败触发器、玩法事件触发器、目标触发器等等。
