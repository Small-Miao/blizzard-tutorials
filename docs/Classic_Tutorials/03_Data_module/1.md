# 数据模块 - 第 1 部分

在这个共三部分的教程中，你将一边制作一张类似《自由之翼》战役第一关的小型冒险地图，一边熟悉《星际争霸 II》编辑器提供的诸多功能。

如果你还没有完成本教程第一部分，可以在 [[这里](../../01_Terrain_Module/1)] 找到它。

如果你还没有完成本教程第二部分，可以在 [[这里](../../02_Trigger_Module/1)] 找到它。

如果你想跳过地形与触发器教程，直接进入本部分，也可以使用我们在前面教程中一直使用的那张地图，见 [[这里](../../02_Trigger_Module/1/#finished-map)]。

## 目标：

通过编辑现有的单位、技能、效果和武器数据，熟悉数据模块。

## 最终效果：

完成本教程后，我们将得到一个经过修改的 Jim Raynor (Commando) 单位：拥有更高的生命值、更高护甲、不同的技能，以及一把经过修改的武器。

![img](001-finishedproduct-modifiedunitingame.jpg)



## 简介

《星际争霸 II》自带数百种预制单位、装饰物、地块集和技能。但如果我们想做一张拥有全新单位或全新技能的地图呢？又或者想做一张让黑暗圣堂武士可以闪现、战列巡航舰护甲为零却拥有离谱生命值的地图呢？这些都要在数据模块里完成。事实上，数据模块几乎允许我们修改《星际争霸 II》中的一切。

在这个教程中，我们会介绍几种修改现有数据的方法，包括修改单位生命值、护甲、初始能量，为单位添加或移除现有技能，以及调整武器的攻击频率和伤害。



### I. 浏览数据编辑器

要打开数据模块，可以按 [F7]，或者点击任意其他编辑器模块顶部工具栏中的 Data Module 按钮。这个按钮的图标是一个蓝色陆战队员。

![img](002-navigating-toolbarbutton.jpg)

第一次看到数据模块窗口时，它可能会显得有些吓人。到处都是小字号文字组成的表格，以及一堆用途一眼看不明白的下拉菜单。不过，一旦理解了这些内容的组织方式，它就没有那么可怕了。

#### A. 数据树

我们可以把《星际争霸 II》中的数据理解成一棵树。每张《星际争霸 II》地图至少会附带一个 “Mod”，其中包含了这张地图可使用的单位、技能、武器、地块集、效果、界面等信息。

![img](003-navigating-datadiagram.jpg)





##### 1. 数据目录

   这根树干会被拆分成不同的数据“目录（Catalog）”。比如 “单位” 是一个目录，“技能” 是另一个目录。这些目录共同构成了完整的游戏数据。

##### 2. 对象

每个目录中都包含一系列“对象（Object）”，也就是该目录中的具体条目。在 单位 目录里，“Marine” 是一个对象，“Stalker” 也是另一个对象。

##### 3. 字段

每个对象都包含一个与之关联的“字段（Field）”列表。这些字段定义了该单位的各种信息。对于 Marine 对象来说，“Life Maximum” 是一个字段，“技能” 也是一个字段。

##### 4. 值

每个字段又包含一个或多个“值（Value）”。有些字段只有单个值，比如 “Life Maximum”；Marine 的 Life Maximum 是 45。有些字段则包含一组值，比如 “技能”，因为每个单位都可以拥有多个技能。



![img](004-navigating-windowbreakdown.jpg)

#### B. 设置工作区

在开始实际操作之前，我们会像触发模块教程中那样先调整几个选项。请注意，这里设置的这些选项只是为了更方便你跟着本教程中的截图操作。编辑器的布局没有绝对正确或错误的方式，所以你也可以多尝试，看看什么最适合自己。

![img](005-navigating-selectedviewoptions.jpg)



##### 1. 查看原始数据
这个选项我们将其关闭。每个对象都有一个供内部引用使用的 ID，同时也有一个作为显示名称的文本值。以我们接下来要修改的 Jim Raynor (Commando) 为例，他的 ID 只是 Raynor，而他的显示名称则是 Jim Raynor (Commando)。如果启用 Show Raw Data，我们看到的将是 Raynor，而不是 Jim Raynor (Commando)。

![img](006-navigating-rawdata.jpg)

##### 2. 将对象列表显示为树形
这个选项我们也关闭。Show 对象列表 As Tree 会根据分类把对象列表整理成文件夹结构，就像浏览电脑里的文件夹一样浏览对象列表。

![img](007-navigating-showobjectlist.jpg)

##### 3. 显示所有对象来源
这个选项我们关闭。修改数据时，我们并不是在修改整个游戏的全局数据，而只是在修改当前这张地图所使用的数据。新修改的数据会存储在我们制作的地图里。如果开启这个选项，那么当我们修改现有单位时，原始数据会显示为一个条目，而我们修改后的数据会显示为另一个条目。由于这里关闭了该选项，当我们修改 Jim Raynor (Commando) 时，列表里只会看到一个条目，而不是两个。
![img](008-navigating-showmultisource.jpg)

##### 4. 显示对象浏览器
这个选项我们打开。Explorer 视图很适合查看数据对象之间的连接关系。比如，当我们正在查看 Jim Raynor (Commando)，如果想快速查看他的武器数据，就可以直接在 Explorer 区域中找到对应武器并选中，而不必再切换到 武器 标签后从整张列表里查找。

![img](009-navigating-showexplorerview.jpg)

##### 5. 表格视图
这个选项我们打开。开启后，我们会看到一个表格：左侧列出对象字段，右侧显示字段值。双击字段或字段值会弹出一个新窗口，让我们编辑这个值。开启 Table View 会自动关闭 Detail View 和 XML View。

![img](010-navigating-tableview.jpg)

##### 6. 详细视图
这个选项我们关闭。开启后，你看到的将不再是字段与值组成的表格，而是用于编辑这些值的完整控件界面。开启 Detail View 会自动关闭 Table View 和 XML View。

![img](011-navigating-detailview.jpg)

##### 7. XML 视图
这个选项我们关闭。开启后，你会看到一个以 XML 格式展示数据的文本编辑器视图。《星际争霸 II》中的所有游戏数据实际上都是以这种格式存储并由游戏读取的。数据模块的主要目的，就是让不熟悉 XML 的用户也能更容易地查看和修改这些数据。关于这个视图，我们会在其他教程中再详细介绍。开启 XML View 会自动关闭 Table View 和 Detail View。

![img](012-navigating-xmlview.jpg)

##### 8. 显示默认值
这个选项我们打开。编辑器不会为每个单位的每个字段都单独保存一份值，而是通过给某些对象提供默认值，再让其他新对象从这些“父对象”那里“继承”数据，从而节省空间。在编辑器中，这些默认值会以灰色显示；若关闭该选项，它们会被隐藏。如果你正在查找某个单位未显式设置、而是继承得到的值，隐藏默认值会让人很困惑。

![img](013-navigating-showdefaultvalues.jpg)

##### 9. 显示高级值
这个选项我们打开。默认情况下，一些需要深入理解游戏数据的字段会被隐藏。高级用户在实现更复杂功能时可能需要使用这些字段。开启后就能看到这些字段。
##### 10. 显示字段类型名称
这个选项我们关闭。字段会按“字段类型”进行分组，因此在 Table View 中，与单位行为或单位技能相关的字段会被归为一组。有时这样有助于查找字段，但如果你不知道目标字段属于哪个类型，也可能反而更难找。现在我们先保持关闭。

![img](014-navigating-showfieldtypes.jpg)

##### 11. 合并结构值
这个选项我们打开。有些对象字段彼此相关。双击其中任意一个相关字段，都会打开同一个窗口，并显示所有相关字段的编辑控件。一个典型例子就是单位命令卡字段。启用该选项后，这些字段会在 Table View 中合并成一个字段，并在字段名后面显示一个 “+”。

![img](015-navigating-combinefields.jpg)

##### 12. XML 语法高亮
这个选项我们打开。有些对象字段彼此相关。双击其中任意一个相关字段，都会打开同一个窗口，并显示所有相关字段的编辑控件。一个典型例子就是单位命令卡字段。启用该选项后，这些字段会在 Table View 中合并成一个字段，并在字段名后面显示一个 “+”。
##### 13. 提交 XML 更改
只有当你在 XML 视图中进行了尚未提交的 XML 数据修改时，这个按钮才会从灰色变为可用。本教程不会使用 XML 视图，因此也不会用到这个按钮。
